# Устранение неполадок

## Vue не подключается к Django / страницы не загружаются

Симптомы: фронтенд (Vue) запущен, Django в консоли «без ошибок», но запросы к API не проходят и страницы не загружаются.

### 1. Убедиться, что Django действительно слушает порт 8000

Запуск **из корня проекта** (там, где лежит `manage.py`):

```bash
python manage.py runserver
```

Должно появиться что-то вроде: `Starting development server at http://127.0.0.1:8000/`.

- Если пишет, что порт занят — закройте другое приложение на 8000 или запустите на другом порту:  
  `python manage.py runserver 8001`  
  и тогда во фронтенде прокси должен указывать на 8001 (см. п. 4).
- На другом компьютере или в другой сети иногда помогает явно слушать все интерфейсы:  
  `python manage.py runserver 0.0.0.0:8000`

### 2. Проверить, что API отвечает

В браузере или через curl откройте:

- **Проверка «жив ли Django»:**  
  `http://127.0.0.1:8000/api/health/`  
  Ожидается ответ в формате JSON: `{"status":"ok"}`.

- **Публичный эндпоинт (без логина):**  
  `http://127.0.0.1:8000/api/news/`  
  Должен вернуть JSON (список новостей или `[]`).

Если по адресу `http://127.0.0.1:8000/api/health/` ничего не открывается или ошибка — Django до запросов не доходит (не запущен, другой порт, фаервол и т.п.).

### 3. Порядок запуска и откуда открывать сайт

Рекомендуемый порядок:

1. Запустить Django: `python manage.py runserver` (оставить терминал открытым).
2. Запустить фронтенд: `cd frontend` → `npm run dev` (оставить терминал открытым).
3. Открывать сайт **по адресу фронтенда**:  
   `http://localhost:5173`  
   Не открывать вкладку с `http://localhost:8000` как «главной» для работы с интерфейсом — порт 8000 это API; интерфейс с прокси к API отдаёт dev-сервер Vue на 5173.

При таком режиме запросы с фронта идут на `http://localhost:5173/api/...`, а Vite проксирует их на `http://localhost:8000/api/...`, поэтому Django должен слушать именно 8000 (или тот порт, что указан в прокси).

### 4. Прокси во фронтенде (Vite)

В `frontend/vite.config.ts` настроен прокси:

- Запросы с пути `/api` уходят на `http://localhost:8000`.

Если Django вы запускаете на другом порту (например 8001), в `vite.config.ts` в `server.proxy['/api'].target` укажите этот порт, например:  
`target: 'http://localhost:8001'`,  
после чего перезапустите `npm run dev`.

### 5. Переменная VITE_API_BASE (фронтенд)

По умолчанию фронт ходит на относительный путь `/api` (и прокси перенаправляет на Django). Если в папке `frontend` есть файл `.env` с переменной `VITE_API_BASE` и там указан полный URL (например `http://192.168.1.5:8000/api`), то:

- запросы пойдут напрямую на этот адрес, минуя прокси;
- на другом компьютере или при доступе по IP нужны CORS (см. п. 6) и доступность этого адреса с вашей машины.

Для локальной разработки на одном компьютере проще **не задавать** `VITE_API_BASE` или оставить `VITE_API_BASE=/api`, чтобы работал прокси.

### 6. CORS (если фронт открыт по IP или другому хосту)

Если заходите на фронт не по `localhost` (например по `http://192.168.1.5:5173`), а запросы к API идут напрямую на Django (из-за `VITE_API_BASE` или иной настройки), браузер может блокировать ответы из-за CORS.

Тогда в окружении Django задайте (или добавьте в `.env` бэкенда):

```bash
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://192.168.1.5:5173
```

Подставьте свой IP/хост и порт. И перезапустите Django.

### 7. Фаервол и антивирус

На некоторых ПК фаервол или антивирус блокирует локальные соединения. Временно отключите их для проверки или добавьте исключение для `python.exe` и порта 8000.

### 8. Два разных окружения (WSL / виртуальная машина / контейнер)

Если Django запущен в WSL или в контейнере, а браузер и Vue — в Windows (или наоборот), то «localhost» у них разный. В этом случае:

- либо запускайте и Django, и Vue в одной среде (оба в Windows или оба в WSL);
- либо настраивайте доступ по IP и CORS (п. 6) и при необходимости привязку Django к `0.0.0.0:8000` (п. 1).

### Краткий чек-лист

- [ ] Django запущен из корня проекта: `python manage.py runserver`
- [ ] В браузере открывается `http://127.0.0.1:8000/api/health/` и возвращается `{"status":"ok"}`
- [ ] Фронт запущен: `cd frontend` → `npm run dev`
- [ ] Сайт открыт по адресу `http://localhost:5173`, а не только по 8000
- [ ] В `frontend` нет лишнего `.env` с `VITE_API_BASE` на другой хост/порт (или CORS и порт настроены)
- [ ] В `vite.config.ts` прокси `/api` ведёт на тот порт, на котором реально работает Django

Если после этого запросы всё равно не проходят — откройте в браузере DevTools (F12) → вкладка Network, обновите страницу и посмотрите, на какой URL уходят запросы и какой ответ (код и тело) возвращает сервер.
