# Логика статистики в админ-интерфейсе

## Откуда берутся данные

Статистика **не хранится отдельно**. Все отчёты считаются **на лету** по данным из БД:

- **CollectionRequest** — заявки на вывоз (дата создания `created_at`, дата завершения `completed_at`, статус, вес `paper_weight_kg`, тип макулатуры `material_type`).
- **RequestMaterialLine** — строки заявки: тип макулатуры и вес по каждой позиции (если заявка создана с несколькими типами).

Никакой отдельной таблицы «сданные материалы» или «агрегаты по учреждениям» не ведётся: всё выводится из заявок и их строк.

---

## Два варианта периода (basis)

Период можно считать по разным датам:

1. **По дате создания заявки** (`basis=created`)  
   Учитываются заявки, у которых **дата создания** попадает в выбранный диапазон.  
   Подходит для отчёта «сколько заявок и объёмов подано за период».

2. **По дате завершения** (`basis=completed`)  
   Учитываются только **завершённые** заявки, у которых **дата завершения** (`completed_at`) попадает в диапазон.  
   Подходит для отчёта «сколько фактически вывезено и сдано за период».

В интерфейсе переключатель: «По дате создания заявки» / «По дате завершения».

---

## Таблица 1: Объём сданных материалов (кг)

**Смысл:** сколько килограмм по каждому типу макулатуры попало в заявки за выбранный период (по выбранной дате — создания или завершения).

**Источники (объединяются):**

1. **Строки заявок (RequestMaterialLine)**  
   По всем заявкам из отфильтрованного набора берутся строки: тип макулатуры + вес. Суммируется вес по каждому типу, считается число заявок (с этим типом).

2. **Заявки без строк**  
   Если у заявки нет ни одной строки в `RequestMaterialLine`, используется «целиком» заявка: один тип — `material_type` заявки, вес — `paper_weight_kg`. Так учитываются старые или упрощённо созданные заявки.

Итог по каждому типу материала: сумма кг и количество заявок. Данные **не кэшируются**, пересчёт при каждом запросе к API.

---

## Таблица 2: Топ организаций по объёму сдачи

**Смысл:** какие учреждения (организации) за период сдали больше всего по весу.

По отфильтрованным заявкам (по `created_at` или по `completed_at` при `basis=completed`) считается по каждой организации:

- сумма `paper_weight_kg` по её заявкам;
- количество заявок.

Сортировка по убыванию веса, в отчёт попадает топ (например, 30). Данные считаются из заявок при каждом запросе.

---

## Таблица 3: Заявки по статусам

**Смысл:** сколько заявок за период в каждом статусе (новые, принятые, завершённые).

По тем же отфильтрованным заявкам (по дате создания или по дате завершения в зависимости от `basis`) считается количество по полю `status`. Данные не хранятся отдельно.

---

## Таблица 4: Динамика объёма по периодам

**Смысл:** как менялся суммарный вес по неделям/месяцам внутри выбранного диапазона.

По отфильтрованным заявкам дата (создания или завершения) округляется до недели или месяца (в зависимости от длины диапазона), затем по каждому такому периоду суммируется `paper_weight_kg`. Результат — временной ряд, без отдельного хранения.

---

## Почему может не быть данных

- В выбранном периоде нет заявок (или нет завершённых заявок при «По дате завершения»).
- Выбран слишком короткий или старый период (например, «1 неделя» при том, что все заявки за прошлый год).
- При «По дате завершения» у заявок не проставлено `completed_at` (статус «Завершён» должен выставляться с сохранением даты завершения).

Рекомендация: попробовать период «1 год» или «Свой период» с широким диапазоном и режим «По дате создания заявки».

Чтобы сгенерировать тестовые данные для проверки статистики:
```bash
python scripts/generate_stats_data.py
```
(требуется предварительно выполнить `load_test_data.py` для создания компаний и организаций).

## API

### Основной endpoint (админ-дашборд)

**GET** `/api/analytics/dashboard/`

Параметры:

- `date_from`, `date_to` — период (по умолчанию последние 365 дней).
- `basis` — `created` (по умолчанию) или `completed`.
- `company_id`, `institution_id` — срез по компании / организации.
- `institution_type`, `material_type` — дополнительные фильтры.

Ключевые блоки ответа:

| Блок | Содержимое |
|------|------------|
| `kpis` | Показатели периода; при фильтре сущности — `is_entity_filtered`, scoped `total_companies` / `total_institutions` |
| `requests_insights` | `funnel`, `backlog` (очередь сейчас), `urgency_breakdown`, `completion_time_buckets`, `estimated_vs_actual`, `status_over_time` |
| `public_pickup` | Заявки с главной страницы: KPI, статусы, материалы, динамика |
| `materials`, `top_companies`, `top_organizations` | Объёмы и рейтинги |
| `bonus_over_time`, `top_point_institutions`, `popular_products` | Программа лояльности |

### Legacy endpoint

**GET** `/api/stats/admin/?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD&basis=created|completed`

Упрощённый ответ: `materials`, `top_organizations`, `requests_by_status`, `weight_over_time`.

## Интерфейс (вкладка «Статистика»)

Пять тематических подвкладок:

1. **Сводка** — KPI периода, тренд, завершённость, топ-3 материала.
2. **Заявки** — воронка, очередь, срочность, SLA, статусы по времени.
3. **Сырьё** — доли материалов, динамика кг, план/факт.
4. **Партнёры** — компании и организации (drill-down по клику).
5. **Сайт и бонусы** — `PublicPickupRequest` + баллы и каталог.
